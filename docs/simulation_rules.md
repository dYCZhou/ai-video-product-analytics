# 模拟规则说明

## 目标

模拟数据不是为了还原某家公司的真实数据，而是生成一个满足业务逻辑、能够支持 SQL 与 Python 分析、能在面试中解释的练习数据集。

## 规则与业务含义

| 规则 | 数据中的实现 | 想模拟的业务现象 |
|---|---|---|
| 渠道质量不同 | 自然、邀请渠道任务活跃度略高，广告渠道略低 | 获客量不等于用户质量 |
| Prompt 商业意图不同 | 商品广告、品牌宣传为高商业意图 | 商用场景更愿意购买高清、去水印等权益 |
| Model_A 快且稳 | 平均耗时低、成功率高、评分一般 | 适合新用户和速度敏感场景 |
| Model_B 质量高但慢 | 评分最高、耗时最长 | 适合高商业价值场景，但等待体验有代价 |
| Model_C 风格强但波动大 | 风格分高、失败和投诉偏高 | 适合二次元和短剧，不宜直接全量 |
| 等待影响行为 | 耗时越长，预览、下载概率越低，退出概率越高 | 技术性能会传导到业务价值 |
| 失败限制行为 | 失败任务只允许 retry 或 exit | 防止逻辑上不可能的下载、分享 |
| 实验影响商业化入口 | treatment 组付费点击概率更高 | 模拟完成页入口强化效果 |
| 订单必须来自点击 | 只有出现 pay_click 的任务才可能产生订单 | 保证付费漏斗可追溯 |
| 评分只属于成功任务 | 失败和超时任务没有 model_scores | 保证评分口径一致 |

## 重要限制

1. 规则由人为设定，因此分析只能证明代码、指标和业务推理能力，不能证明真实产品效果。
2. A/B 实验的效果被写进生成机制，显著性检验用于练习方法，不能作为真实上线依据。
3. 数据没有真实埋点丢失、作弊流量、跨端身份合并、退款和实验污染等复杂问题。
